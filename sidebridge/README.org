* sidebridge

Async radio control abstraction layer for amateur radio transceivers. Defines a modular trait hierarchy where drivers implement only the capabilities their hardware supports. Includes an Icom CI-V parser/codec and utility binaries for TCP-to-serial bridging.

** Trait hierarchy

| Trait | Purpose | IC-705 | FT-891 | IC-781 |
|-------+---------+--------+--------+--------|
| =Radio= | Frequency, mode, PTT | yes | yes | yes |
| =RadioInfo= | Model name, capabilities | yes | yes | yes |
| =RadioMeter= | S-meter, SWR, ALC, RF power | yes | yes | yes |
| =RadioScope= | Spectrum/waterfall | yes | no | no |

** Core types

- =Radio= - async trait: =set_frequency= / =frequency=, =set_mode= / =mode=, =set_ptt= / =ptt=
- =Mode= - LSB, USB, AM, CW, RTTY, FM, CW-R, RTTY-R, DATA-LSB, DATA-USB, DATA-FM
- =Capabilities= - runtime feature discovery (meter, scope, SWR, memory channels)
- =ScopeFrame= - spectrum scope data for waterfall rendering
- =RadioError= - typed errors: IO, Timeout, Protocol, Busy, NotSupported, CommandFailed

** Icom CI-V

The =civ= submodule (under =drivers/icom=) provides a complete CI-V protocol stack:

- =CivFrame= - parsed CI-V frame (dest, src, command)
- =CivCommand= - decoded commands: frequency, mode, PTT, S-meter, waterfall, OK/NG
- =CivCodec= - =tokio-util= =Decoder=/=Encoder= for framing CI-V over byte streams
- =CivPacket= - stack-allocated packet for construction and serialization
- =parser= - =nom=-based frame parser with BCD frequency encoding/decoding

** Binaries

In the examples below, =shack= is used as a hostname for the remote machine (e.g. a Raspberry Pi reachable via tailscale or SSH config).

*** serial-bridge

Transparent TCP-to-serial bridge. Works with any serial protocol (Icom CI-V, Yaesu CAT, etc). Run on a machine connected to the radio, access remotely via SSH port forwarding or directly over tailscale.

#+begin_src bash
  # On the Pi (or local machine)
  serial-bridge --serial /dev/ic-705a --listen 0.0.0.0:9000

  # From remote, via SSH tunnel
  ssh -L 9000:localhost:9000 shack
#+end_src

*** civ-client

Monitor and decode CI-V traffic from a bridge.

#+begin_src bash
  civ-client shack:9000
#+end_src

*** civ-poll

Poll frequency and S-meter from an Icom radio via CI-V. Connects directly over serial or remotely via TCP through serial-bridge.

#+begin_src bash
  # Direct serial connection
  civ-poll serial:///dev/ic-705a

  # With custom baud rate
  civ-poll serial:///dev/ic-705a?baud=9600

  # Via serial-bridge over TCP
  civ-poll tcp://shack:9000
#+end_src

*** Cross-compile and run via SSH

The binaries can be cross-compiled for a Raspberry Pi and executed remotely:

#+begin_src bash
  # Cross-compile for aarch64 (Pi 4/5)
  cross build -p sidebridge --release --target aarch64-unknown-linux-gnu

  # Copy to the Pi
  scp target/aarch64-unknown-linux-gnu/release/serial-bridge shack:/tmp/
  scp target/aarch64-unknown-linux-gnu/release/civ-poll shack:/tmp/

  # Start the bridge on the Pi
  ssh shack '/tmp/serial-bridge --serial /dev/ic-705a --listen 0.0.0.0:9000'

  # Poll from local machine via TCP
  civ-poll tcp://shack:9000

  # Or poll directly on the Pi
  ssh shack '/tmp/civ-poll serial:///dev/ic-705a'
#+end_src

** Usage (library)

#+begin_src rust
  use sidebridge::{Radio, Mode, RadioMeter};

  // Any radio driver that implements Radio
  async fn tune_and_read(radio: &(impl Radio + RadioMeter)) -> sidebridge::Result<()> {
      radio.set_frequency(14_074_000).await?;
      radio.set_mode(Mode::DataUsb).await?;

      let s = radio.signal_strength().await?;
      println!("S-meter: {s}");
      Ok(())
  }
#+end_src

** Design rationale

- *Small core trait* - =Radio= has only frequency/mode/PTT. Every radio from a vintage IC-781 to a modern IC-705 can implement this.
- *Capability traits* - =RadioMeter=, =RadioScope=, =RadioInfo= are separate. Drivers only implement what the hardware supports. No dummy methods.
- *Protocol-agnostic* - Icom CI-V, Yaesu CAT, Kenwood TS-xxx all hide behind the same =Radio= trait. Protocol details live in driver modules.
- *Symmetric get/set* - =frequency()= / =set_frequency()= instead of a monolithic =state()= snapshot. Cleaner for both polling and event-driven radios.
- *Unix philosophy* - Local serial access by default. For remote radios, use SSH port forwarding or =socat= -no custom networking protocol needed.
