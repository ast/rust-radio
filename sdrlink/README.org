* sdrlink

OpenWebRX-style web SDR with a Rust backend and a SolidJS frontend. An
AirspyHF+ feeds an =IqBroker= fan-out that drives both a shared FFT
spectrum worker and an FM demod pipeline. Clients authenticate over
HTTP, open a WebSocket for signaling/control, and negotiate a WebRTC
peer connection that carries Opus audio on a media track and binary
spectrum frames on an unreliable/unordered data channel.

** Status

- [X] TOML config + argon2 user management (=user-add= / =user-remove= / =user-list=)
- [X] =IqBroker= fan-out designed for N consumers
- [X] Shared 32k FFT spectrum worker, quantized u8 PDS broadcast
- [X] AirspyHF+ hardware source (fake oscillator kept for tests)
- [X] Per-client viewport min/max decimation
- [X] FM demod pipeline (768k → 192k IQ → demod → 96k → 48k mono, Opus 20 ms)
- [X] WebRTC audio (Opus) + unreliable =spectrum= data channel
- [X] Runtime retune via wheel-scrollable VFO digits (GHz/MHz/kHz/10 Hz)
- [X] Selectable perceptual colormaps (inferno, magma, plasma, viridis, cividis)

** Build

System deps:

#+begin_src bash
  # Debian/Ubuntu
  sudo apt install libasound2-dev cmake nodejs npm
#+end_src

Build the frontend first so =rust-embed= picks up =frontend/dist=:

#+begin_src bash
  cd frontend && npm install && npm run build && cd ..
  cargo build -p sdrlink
#+end_src

Run the test suite:

#+begin_src bash
  cargo test -p sdrlink
#+end_src

** Run

Start the server against the checked-in example config:

#+begin_src bash
  just run           # debug build
  just run-release   # release build — use this for live radio
#+end_src

The release build matters: debug drops IQ samples at 768 ksps on modest
hardware.

For a persistent local config, copy the example first:

#+begin_src bash
  cp sdrlink.example.toml sdrlink.toml
  cargo run --release -p sdrlink -- serve
#+end_src

Requires an AirspyHF+ plugged into USB. Open =http://localhost:8081/=
and log in with the template credentials:

- username: =sm6wjm=
- password: =sm6wjm=

The landing view shows a scrolling waterfall of the tuned passband.
Scroll over the GHz/MHz/kHz/10-Hz digit groups in the =tuning= panel to
retune; the change is broadcast to every connected client. Audio plays
in the =<audio>= element below the waterfall.

** User management

#+begin_src bash
  cargo run -p sdrlink -- user-add <username>      # prompts for password
  cargo run -p sdrlink -- user-remove <username>
  cargo run -p sdrlink -- user-list
#+end_src

All three take an optional =--config <path>= (default =sdrlink.toml=).

** Config (=sdrlink.toml=)

#+begin_src toml
  [server]
  listen_addr = "0.0.0.0:8081"

  [sdr]
  center_hz = 102_700_000.0   # FM broadcast example
  samplerate = 768000         # AirspyHF native; clean decimation to 48 kHz audio
  fft_len = 32768             # 23.4 Hz/bin at 768 kHz
  fft_rate_hz = 20            # frames per second

  [[users]]
  username = "sm6wjm"
  password_hash = "$argon2id$..."
#+end_src

Defaults (=samplerate=, =fft_len=, =fft_rate_hz=) kick in if omitted.
=center_hz= is overridden at runtime by the browser tuner.

** Architecture

#+begin_src text
  airspyhf ── IqBroker ──┬──► spectrum_worker ── broadcast<Arc<[u8]>> ──► DC pump ──► "spectrum" DC
  (Device      fan-out   │    (shared 32k FFT, u8 dB)   per-client min/max decim
   callback)             │
                         └──► fm_pipeline ──► broadcast<AudioFrame> ──► audio track pump
                              (rotator → FM_64 ÷4 → FmDemod → HB_35 ÷2 ×2 → Opus)
#+end_src

Building blocks come from sibling workspace crates: =airspyhf=,
=doublemap= (SPSC memfd ring), =pool= (RAII =BufferPool=), =spectrum=
(=Analyzer=), =filters= (=FirDecimator=, =ComplexRotator=, =FmDemod=,
kernels =FM_64= and =HB_35=), =signals= (fake oscillator for tests).

** Wire protocol

=/api/ws?token=...= carries JSON signaling only. All messages are
adjacently tagged =({ "type": ..., "payload": ... })=.

Server → client:

- =Hello= — =center_hz=, =samplerate=, =fft_len=, =fft_rate_hz=
- =Answer= — SDP answer
- =IceCandidate=
- =CenterChanged= — =hz= (broadcast whenever any client retunes)

Client → server:

- =Offer= — SDP offer (with one =recvonly= audio transceiver and a
  =spectrum= data channel configured =ordered: false, maxRetransmits: 0=)
- =IceCandidate=
- =SetViewport= — =start_hz=, =stop_hz=, =pixels= (server clamps to
  passband and does the min/max decimation per-client)
- =SetCenter= — =hz= (triggers =airspyhf_set_freq= + broadcast)

The browser initiates the PeerConnection after receiving =Hello=, so
the page is mounted and the waterfall texture allocated before any
spectrum/audio flows.

*** Data channel: =spectrum=

Unreliable/unordered datagrams. Each message is one frame:

#+begin_src text
  [u16 le pixels][u8 min[pixels]][u8 max[pixels]]
#+end_src

The server decimates the shared PDS to the client's current viewport
width using per-column min/max (preserves narrow peaks at any zoom).
The client uses =max= for the waterfall row.

*** Media track: audio

Opus, 48 kHz mono, 20 ms frames. Attached to the same PeerConnection;
the browser plays it straight out of an =<audio>= element.
